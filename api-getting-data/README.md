I've noted before that my past assignment was on Pokemon because it was one of my most beloved games. I decided to do this one on Harry Potter, as the series is one of my all time favorites, and I basically play Quidditch in real life.
While I was doing this API assignment, the Fandom API required that a descriptive user-agent was used. However, PotterDB did not require anything at all. 
For rate limits, I couldn't find a specified time limit for either API. So I kept timesleep just in case it required one and I couldn't see it. 
The data structure was shaped as Fandom having pages, categories, and links. PotterDB gives clean links like to the houses and wiki, but when I was doing this, I realized name search is literal, and has no room for error. For example, I've printed a potterdb_charactersjson. This gives what someone might try to search up, or scrape, and the literal outcome printed. When you also run the getting_culture.py, another noteable outcome is that "Ginny" cannot be found. It takes the fullest name the data has, so it counts Ginny as Ginevra. 
Fandom is a for-profit company. They host volunteer editors work. PotterDB, on the other hand, is one person's own project that scrapes the wiki. If Fandom blocks scraping, PotterDB stops updating.
